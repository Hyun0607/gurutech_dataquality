# stdtool — 표준화 점검 프로그램

표준구조 매크로(`표준구조_작업_전체`, `메타_작업_전체`)를 Python으로 옮기고, 그 위에 고도화 3가지를 더한 프로그램입니다.

- ① 도메인 사전: 도메인을 사람이 따로 추가하는 일 없애기
- ② 공통표준 유의어·금칙어 대응: 이음동의어·금칙어로 쓴 컬럼을 찾아 사전점검(기준1)에서 알려 주기 (정의서는 실제 DB 컬럼 그대로)
- ③ DB표준적용 사전점검: 점검요청 전에 오류와 예상 적용률 계산

## 설치

```
cd stdtool
uv sync
```

## 화면으로 쓰기

```
uv run stdtool-gui
```

- 처음에는 **설정**에서 제정일자를 입력합니다. 표준 사전은 **사전 파일**(팀원 기본, 프로그램에 같이 들어 있음) 또는 **MySQL**(관리자 원본, 비밀번호는 Windows 자격 증명 관리자에 저장)에서 읽습니다. 평가대상 DB 목록(기관명·순번·정보시스템명·한글 DB명·영문 DB명 엑셀)은 사전에 들어 있고, 설정에서 다시 가져올 수 있습니다.
- 위쪽에서 **기관 → 시스템**을 고릅니다. 시스템 상자에는 고른 기관의 DB만 나옵니다. 산출물 파일의 DB명은 시스템명이고, 한 시스템에 DB가 여러 개면 `시스템명_한글DB명`입니다.
- 메타 파일을 고르면(찾기, 또는 창에 끌어다 놓기) 기관·시스템이 파일의 기관명·정보시스템명(B·C열, DB가 여럿이면 한글·영문 DB명 O·P열)으로 자동으로 정해집니다. **▶ 실행** → 위쪽 **진행 패널**에 17단계(사전 읽기 → … → 테이블관계정의서 → 연계 정의서)가 실시간으로 표시되고, 끝나면 왼쪽 메뉴에서 지표별 결과를 봅니다: 표준 2-1-3(표준 정의·적용률·사전 관리), 구조 2-1-4(구조 정의·테이블관계정의서 2-1-4-1·구조 현행화 2-1-4-2), 연계 2-1-5(관리 정보 정의 2-1-5-1·송수신 내역 2-1-5-2).
- 산출물은 **바탕화면**의 `기관_DB` 폴더 하나에 모이고, 그 안에서 `표준_구조_연계` · `수동등록` 폴더로 나뉩니다. 위치는 설정에서 바꿀 수 있습니다.
- 사전점검 오류는 **품질·표준관리 통합시스템과 같은 묶음·오류명·오류상세내용**으로 보입니다 (예: `[ DB표준용어 ] 공통표준용어 준용 점검` → `불일치(영문약어명)`). 공통표준 준용 점검은 통합시스템처럼 준용 대상(용어명·영문약어명·이음동의어가 같은 것)만 보고, 한 건에 오류 하나만 냅니다 (NUMBER=NUMERIC, DATE=DATETIME). 통합시스템에 없는 점검(빈 값 등)은 `프로그램 추가 점검`으로 따로 묶습니다. 코드는 `용어-10`, `현행화-05`처럼 영역 이름으로 붙습니다.
- 연계 정의서(2-1-5-1·2)는 만들어진 **컬럼정의서**를 그대로 따릅니다 (PK·FK·개인정보 여부만 메타에서 가져옴).
- 화면은 늘 고도화 방식으로 실행합니다. `stdtool` 폴더에 `config.toml`이 있으면 그 고급 설정을 바탕으로 씁니다.
- 연계 화면에서 체크·주기·활용기관을 고치고 **양식 만들기**를 누르면 2-1-5-1·2-1-5-2를 다시 만듭니다.

- **요약 → 시스템 정보**: 기관·정보시스템과 DB별 **업무분류체계**(메타 파일 Q열)를 보여 줍니다. 기관 메타시스템에 올릴 때 넣을 값을 '복사'로 바로 가져갈 수 있고, 비어 있으면 알려 줍니다.
- **회차 기록**: ▶ 실행할 때마다 결과 요약과 오류 목록(점검 화면·이름·영문약어명·오류명)이 사용자 폴더(`%APPDATA%\stdtool\history.sqlite`)에 쌓이고, 산출물 폴더에 `실행기록.xlsx`도 남습니다. 두 회차를 고르면 지표 변화와 고쳐진·새로 생긴·그대로인 오류를 보여 줍니다. 메타 파일 내용은 남기지 않습니다 (파일 이름만).

## 예방적 품질관리 (2-1-2)

왼쪽 메뉴 **예방적 품질관리**는 메타 파일·▶ 실행과 상관없이 움직입니다. 기준(회차 기간, 사업유형 키워드, 매뉴얼 3.2.1.3 적용표, 지표별 산출물, 매뉴얼 3.2.2 요구사항 문안)은 `stdtool/templates/예방적품질관리_기준.xlsx`이고, 화면의 **기준 엑셀 열기**는 사용자 폴더에 복사해 엽니다. 내년 공지가 나오면 '회차' 시트의 기간을 고칩니다.

- **대상 사업**: 사업단의 `이행점검(N차) 대상.xlsx`를 끌어다 놓으면 평가대상 DB 목록의 기관 사업만 골라 단계, 사업유형(사업명 키워드), 대응 지표(O / 금액 확인 후 △), 다음 회차 예측(다음 회차 완료 전환 예상 · 내년 완료단계 후보 · 기간 연장 확인)을 보여 줍니다. 읽은 회차는 `history.sqlite`에 남아 다음 회차 파일과 비교됩니다(이전 회차 단계). 사업유형·이관 칸은 두 번 눌러 고치고(고친 값은 다음 회차에도 이어짐), 표 위의 단계·분류·사업유형·사업종료(회차 기간)·기관 상자로 거릅니다. 금액은 발주단계 점검에서 RFP로 채웁니다. 예측 규칙(의견 있음 + 종료일이 다음 회차 완료 기간 안)은 2026 1차→2차 실제 전환 41건 중 37건 적중.
- **IRM 사전협의(총괄) 목록으로 먼저 예측**: 대상 사업 화면에 IRM에서 내려받은 `사전협의(총괄) 목록_*.xlsx`를 넣으면 사업단 대상 목록이 나오기 전에 판정합니다. 기준1(발주): 반려/취소·신청대기·신청반려·결과유형 빈칸 제외 → 통보일(검토완료(예정)일, 보완 후 협의는 반영계획 점검등록일)이 '회차' 발주 기간 안이면 1차(~4.30)·2차(~8.31), 그 뒤는 내년. 기준2(완료): '21.3.12 이후 신청 + DB 분야 의견 → 사업완료 종료일(없으면 계획 종료일로 '완료 예정')로 1차·2차·내년. DB 의견수 0은 대응 불필요. 사업유형은 IRM '사전협의 사업유형', 금액은 예산총액. 한국연구재단 11건이 사업단 1·2차 목록과 모두 일치(2026-11-05). IRM 예측은 사업단 회차 기록을 덮어쓰지 않습니다.
- **발주단계 점검**: RFP(hwpx·hwp)를 넣으면 사업비를 읽고(대상 사업 금액으로 저장), 요구사항 블록(고유번호·요구사항 명칭) 중 DAR 이름으로 지표별 반영을 봅니다. DAR이 아닌 요구사항·본문에만 있으면 확인필요, 없으면 미반영이고, 그 사업 유형·금액에 맞는 매뉴얼 3.2.2 문안을 '문안 복사'로 줍니다. 한국연구재단·용인시의 보완 전후 RFP로 NIA 지적(4.2, 1.1)이 그대로 나오는지 확인했습니다.
- **완료단계 점검**: 완료·감리보고서와 **IRM에 등록한 산출물**을 함께 넣습니다 ([파일 추가]·[폴더 추가]·끌어다 놓기, 여러 번 나눠 넣어도 '제출 파일' 목록에 쌓이고, [선택 빼기]·[모두 지우기]로 뺌). 완료보고서에 없어도 IRM 산출물에 있으면 인정되기 때문입니다. 보고서·문서(pdf·hwpx·hwp)는 본문에서 지표별 수행 내역(쪽 번호)을 찾고, 그 밖의 파일(xlsx·pptx·docx 등)은 파일 이름(기준 엑셀 '세부기준'의 파일 단어)으로 산출물을 알아봅니다. zip은 안의 파일 이름을 모두 보고 안에 든 문서는 본문도 읽습니다 (윈도우 한글 파일 이름 포함). 근거는 완료·감리보고서 쪽이 먼저 나옵니다. 이미 넣은 파일은 다시 넣어도 한 번만 들어갑니다 (보고서·문서·zip은 내용이 같으면, 이름으로 알아보는 산출물은 내용과 이름이 같으면 중복 — 복사본·이름만 바꾼 보고서도 걸러짐). 사업은 처음 넣은 파일로만 고르므로 나중에 더한 산출물이 사업을 바꾸지 않습니다. 빠진 지표는 '가이드 폴더 만들기'로 기관 담당자에게 전달할 보완 자료(가이드·인정 산출물 안내·사업단 예시)를 모읍니다.
  - 세부 기준 18개(1.1(1)~4.2(2)) 단위로 Y / N / -를 매기고 품질·표준관리 통합시스템처럼 한 줄 표와 진단결과반영비율(Y÷(Y+N))을 보여 줍니다. 기준별 단어·파일 단어·생략 유형·검토의견 문구는 기준 엑셀 '세부기준' 시트(사업단 '사업 완료단계 진단결과' 문구). 4.2(1) 개방은 매뉴얼상 개방 대상일 때만이라 기본 '-'. 지표마다 (1)·(2) 중 하나만 충족하면 되므로 하나가 Y면 나머지는 '-'. 판정은 화면에서 고칠 수 없고(기준 엑셀 '세부기준'을 고침), 표의 칸을 누르면 누락 이유·근거·필요/인정 산출물이 나옵니다. 감리보고서는 인사말의 '…가 수행하는 ‘사업명’에 대한 감리'에서 사업명을 읽습니다. 결과 엑셀에 사업단 양식의 '완료단계 진단결과'·'검토의견' 시트가 추가됩니다.
- **이행점검 결과 엑셀**(발주·완료 화면의 '결과 엑셀 저장'): 사업단 결과 파일과 같은 이름·양식 `예방적 품질관리 진단 이행점검(N차)_기관_날짜.xlsx` — 1. 사업 진단결과(지표 9칸 점검 완료 / 보완 필요·보완서류 필요 / -, 비고), 2. 보완 사항(보완할 지표의 진단기준 ①② · 현재 상태 · 보완 방법: 발주는 넣을 DAR 문안, 완료는 인정 산출물), 지표별 상세. 점검할 때마다 `history.sqlite`에 남아 같은 기관이면 그 평가연도의 발주·완료 점검이 회차가 달라도 한 파일(예: 이행점검(1·2차))에 모입니다.
- **완료단계 가이드 폴더**('가이드 폴더 만들기'): **보완이 필요한 지표만** `코드 지표명` 폴더를 만들어 가이드(사업단 '완료 단계 산출물 제출 가능 가이드 모음')·증빙기준 그림·제출 안내.txt·예시(사업단 완료단계 산출물 예시)를 넣고, 맨 위에 감리·완료보고서 예시와 이행점검 결과 엑셀. 자료는 `stdtool/templates/예방적품질관리_자료`(약 57MB)에 같이 넣었습니다.
- 대상 사업 결과 엑셀: 대상 사업 분류(요약·관리 기관 사업·완료 전환 예상·내년 후보·확인필요·지표별 필요 산출물), 점검 결과(통합시스템 형식 진단결과 점검완료/보완필요/-, 지표별 상세, 넣을 요구사항 문안 또는 제출 안내).
- RFP·보고서 본문은 저장하지 않습니다. 판정과 근거 문장만 결과 파일에 남습니다.

## 기관표준 점검 · A값 (2-1-3-1)

표준 정의 화면 맨 위 카드. 메타 파일·▶ 실행과 상관없이, 위에서 고른 기관의 기관표준(표준 사전에 있는 것)이나 [기관표준 파일 넣기]로 넣은 용어·단어·도메인·코드 xlsx로 점검합니다.

- A값(기관별 A값 자가진단 가이드 2026.10): **1** 공통표준을 준용해 기관표준 정의 / **0.9** 정의했으나 미준용 / **0.8** 미정의. 정의는 용어·단어·도메인·코드 **전부** (완전성 점검 대상 − 오류) > 0, 준용은 용어·단어·도메인 **전부** (공통표준 준용 대상 − 오류) > 0. 대상 0건은 통과가 아닙니다. 2-1-3-1 점수 = 평가대상 DB 점수 합계 × A ÷ 평가대상 DB 수.
- 통합시스템 **엑셀 다운로드**(완전성·공통표준준용 결과가 든 파일)를 넣으면 그 결과로 **실제 A값**, **엑셀양식 다운로드**(등록 양식)면 프로그램이 같은 규칙(안내서 p.74~78, 사전점검과 같은 코드 + 코드 중복 점검)으로 **예상 A값**. 예술경영지원센터 점검결과 파일로 프로그램 점검이 영역별 대상·오류 건수까지 통합시스템과 같음을 확인했습니다(용어 3건 모두 오류 → A=0.8).
- 항목별 A(세부 안내서 p.78 예시: '표준용어 점수 × 0.9')도 같이 보여 줍니다. 가이드와 안내서 표현이 달라 둘 다 표시합니다.
- 결과 엑셀: 요약(A값·영역별 건수·깎인 이유) · 점검 오류.

**기관표준 준용**: 표준 사전(DB·사전 파일)에 그 기관의 기관표준이 있으면 ▶ 실행 때 기관표준여부가 자동으로 Y가 되어 매크로 '기관표준 매핑'을 하고, 사전점검에 **[ DB표준용어 ] 기관표준용어 준용 점검**(안내서 p.79: 용어명·영문약어명이 같은 기관표준용어와 이름·약어·타입·길이 비교)이 더해집니다. 없으면 N(미준용).

기관표준 DB: 한 DB(std_dict) 안에 `inst_std`(기관 목록)·`inst_term`·`inst_word`·`inst_domain`·`inst_code` 5개 테이블을 두고 기관명 열로 나눕니다 (기관이 늘어도 테이블은 그대로). 한 기관을 다시 넣으면 그 기관 행만 바뀝니다.

```
uv run stdtool db inst-sql "계룡시_기관표준" "예술경영지원센터_기관표준" --out sql/기관표준.sql   # DBeaver용 스크립트
uv run stdtool db inst-import "계룡시_기관표준" --file stdtool/data/std_dict.sqlite           # 배포용 사전 파일에 바로
uv run stdtool db inst-import "계룡시_기관표준" --config config.toml                            # MySQL에 바로 (테이블이 있어야 함)
```

- 폴더 이름의 기관명은 평가대상 목록 이름으로 맞춥니다 (계룡시 → 충청남도 계룡시). 다르면 `--org`.
- 배포 사전(`stdtool/data/std_dict.sqlite`)에는 충청남도 계룡시·예술경영지원센터가 들어 있습니다. MySQL에서 `db export`(또는 build.py)로 사전 파일을 새로 만들 때 MySQL에 기관표준 테이블이 있으면 같이 들어가므로, 그 전에 DBeaver 스크립트 [sql/기관표준_계룡시_예술경영지원센터.sql](sql/기관표준_계룡시_예술경영지원센터.sql)을 실행해 두세요.

## 팀 배포 (exe)

```
uv run python packaging/build.py              # MySQL 사전으로 사전 파일을 새로 만들고 → exe → zip
uv run python packaging/build.py --skip-dict  # 사전 파일은 그대로
```

- 결과: `dist/stdtool/stdtool.exe`(폴더형, 약 90MB)와 `dist/stdtool_v{버전}.zip`(약 40MB). zip 안에 팀원용 [설치 안내](packaging/설치%20안내.txt)가 들어갑니다.
- 팀원 PC: 압축 풀고 실행. 처음 켜면 같이 넣은 사전 파일(`stdtool/data/std_dict.sqlite`)을 사용자 폴더로 복사해 씁니다. 새 버전 exe에 든 사전이 사용자 폴더 사전보다 새것이면(만든 날짜 비교) 켤 때 자동으로 바꿉니다 (설정에서 직접 고른 사전 파일은 그대로). 파이썬·MySQL·비밀번호가 필요 없습니다.
- 새 사전: 관리자가 설정 → MySQL → **사전 파일 만들기**(또는 `stdtool db export`)로 만든 `.sqlite`를 팀 공유 폴더에 두면, 팀원 프로그램이 켤 때 더 새 사전이 있는지 보고 받을지 묻습니다 (설정 → 표준 사전 → 공유 폴더).
- 새 버전: `stdtool/__init__.py`의 `__version__`을 올리고 다시 만듭니다. 설정·사전·회차 기록은 사용자 폴더에 있어서 덮어써도 남습니다.
- 배포본 확인: 환경변수 `STDTOOL_SELFTEST=그림.png`로 exe를 켜면 화면을 그림으로 남기고 닫습니다 (`STDTOOL_SELFTEST_OUT=폴더`면 ▶ 실행까지 하고 그 폴더에 산출물). `STDTOOL_HOME`으로 사용자 폴더를 바꿀 수 있습니다.
- 아이콘은 `packaging/make_icon.py`, 글꼴은 Pretendard(OFL, `ui/assets/fonts`)입니다.

## 표준 사전 DB (MySQL)

1. DBeaver에서 [sql/schema.sql](sql/schema.sql)을 실행해 `std_dict` DB와 테이블을 만듭니다.
2. 설정 파일 `[db]`에 접속 정보를 적고, 비밀번호는 환경변수 `STDTOOL_DB_PASSWORD`에 넣습니다.
3. 가져오기: 매크로 파일의 공통표준·Code_type·Code_tail 시트와 공통표준 원본 3개를 DB에 넣습니다.

```
uv run stdtool db import --config config.toml [--only macro|common] [--replace-codes]
uv run stdtool db import --config config.toml --eval-list "전체 평가대상 DB리스트.xlsx"   # 기관·시스템 목록만
uv run stdtool db status --config config.toml
uv run stdtool db export --config config.toml --out std_dict.sqlite   # 팀원 배포용 사전 파일
```

- 가져오기는 기존 내용을 지우고 새로 넣습니다 (버전 관리 없음).
- Code_type·Code_tail은 직접 행을 추가해 쓰는 테이블이라, 가져오기는 매크로에서 온 행(`added_by = 'MACRO'`)만 다룹니다. 매크로 행이 없을 때만 넣고, 다시 넣으려면 `--replace-codes`를 붙입니다. 직접 추가한 행은 어느 경우에도 지우지 않습니다.
- 추가 타입·꼬리는 [sql/code_additions.sql](sql/code_additions.sql)을 DBeaver에서 실행해 넣습니다 (순번 1001부터, 매크로 행 뒤에 찾음).
- 사전 파일은 MySQL과 같은 테이블·같은 값에 `dict_info`(만든 날짜·만든 사람·공통표준 차수)를 더한 SQLite 파일입니다. `[db] file = "std_dict.sqlite"`이면 명령줄도 MySQL 대신 그 파일을 읽습니다.
- `[db] use = true`이면 `run`·`check`가 매크로 파일과 공통표준 원본 대신 DB에서 사전을 읽습니다. 기관표준여부는 DB에 그 기관(`org_name`)의 기관표준이 있으면 Y, 없으면 N으로 자동으로 정합니다 (위 '기관표준 점검 · A값').

## ② 표준 매핑 검토 순서

1. 매핑 결과(구분, 판정 단계, 권고 표준용어, 후보 3개, 금칙어)는 화면 **표준** 메뉴와 사전점검 기준1에서 봅니다.
2. 치환 권고는 기본으로 적용하지 않습니다(`auto_apply = false`). 적용하면 컬럼정의서·수동등록의 컬럼명·타입이
   실제 DB와 달라집니다 (목재정보서비스 시스템 등록본과 대조했을 때 98개 컬럼이 달라짐).
3. 꼭 바꿔야 하면 `auto_apply = true` 또는 검토 파일을 `--review`로 넘깁니다.

| 구분 | 뜻 | 기본 처리 |
|---|---|---|
| 표준 그대로 | 용어명 또는 영문약어명이 공통표준과 같음 | 매크로 공통표준 매핑이 처리 |
| 치환 권고 | 표기 차이·이음동의어·금칙어 단어를 바꾸면 공통표준과 같음 | 알려 주기만 (적용 안 함) |
| 비표준 매핑 대상 | 비슷한 공통표준 후보가 있음 | 사람이 골라야 적용 |
| 대응 공통표준 없음 | 후보도 없음 | 기관 자체 용어로 생성 |

## 산출물

`output_dir/{기관}_{DB}/` 아래 세 폴더에 만들어집니다.

| 파일 | 내용 |
|---|---|
| `표준_구조_연계/테이블정의서_…`, `컬럼정의서_…`, `DB표준도메인_…`, `DB표준용어_…`, `DB표준단어_…` | 매크로 정의서_내보내기 파일 (`! 제거된항목`은 내보내지 않음) |
| `표준_구조_연계/물리ERD대체_테이블관계정의서_…` | 물리 ERD 대체 테이블관계정의서 (2-1-4-1). PK·FK가 없어 컬럼 이름으로 부모·자식을 짐작 (같은 키 컬럼 중 이름이 맞는 테이블이 부모, `X_SUB_TB`·`X_FILE`은 `X`의 자식). 구조 정의 화면에서 틀린 관계를 빼고 다시 만듭니다 |
| `수동등록/수동등록_{DB}[_n].xlsx` | 5,000행 단위로 나눈 수동등록 파일. 머리글·시트명은 기관메타에 올라간 파일과 같게, 길이 -1(MAX)은 1로 |
| `표준_구조_연계/2-1-5-1 연계데이터 목록 정의서_…`, `2-1-5-2 연계데이터 관리현황 자료_…` | 고른 컬럼 하나로 만든 연계 제출 양식, 1행 (추천 순서 PK → 식별자·코드 → FK → 명칭, 점검 결과 오류 없음, 점검 일시는 올해 6월~실행일 평일 무작위) |

사전점검, 구조 현행화, 표준매핑, 변경이력, 연계후보는 파일로 내지 않고 화면에서 봅니다.
(`stdtool precheck`·`stdtool currency` 명령은 따로 보고서 파일을 씁니다.)

## 방식

- **매크로 방식** (`--macro-mode`): 매크로와 같은 결과를 냅니다. ①②는 하지 않고 ③ 사전점검만 합니다.
- **고도화 방식** (기본): 매크로 흐름에 ①②를 더합니다.

## 구조

```
stdtool/
  vba.py          VBA 내장 함수·엑셀 동작 재현 (Trim, Val, CleanText, Find …)

    cleanse.py      메타→RAW, 값 정제, ① 타입 파싱·길이 정책
    mapping.py      기관표준·공통표준 매핑, DB표준 적용
    synonym.py      ② 유의어·금칙어 매칭
    naming.py       도메인명 규칙, ① 분류 보조·약어·재사용

    enhance.py      ① 용어 도메인 보장

    precheck.py     ③ 사전점검
    relation.py     테이블관계정의서 (물리 ERD 대체, 이름으로 부모·자식 짐작)
```
